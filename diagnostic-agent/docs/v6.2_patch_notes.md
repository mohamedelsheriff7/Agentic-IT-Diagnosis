## Changes

1. **VPN scope and negation.** “No colleagues can connect” and “None of my colleagues can connect” now mean peer failure. Self-correcting and conflicting answers request clarification instead of selecting the first positive phrase. Double negatives remain unclassified.
2. **Specific VPN errors.** Reported local-configuration errors remain distinct from credential/authentication errors. The visible hypothesis retains that distinction without claiming a verified faulty component.
3. **Negative observations.** DNS summaries now include failed direct-IP access and failed external websites, as well as supporting observations. These failures do not establish the supported DNS symptom pattern.
4. **Corrections after handoff.** Explicitly marked factual corrections are handled separately from acknowledgements. Backend mode reads the current ticket, persists USER_RESPONSE evidence using the affected person's actual ID, records a new HUMAN_REQUIRED/ESCALATE result, and retains the returned evidence/result IDs. The earlier diagnosis is cleared pending Supervisor review. No new diagnosis, repair or assignment is inferred. The pending review state survives fresh-chat resume. Resolved/closed tickets remain read-only.
5. **Visible tool gaps.** Unknown results and unavailable/timed-out diagnostic checks are explained in conversation, alongside the next useful question. Missing checks are not treated as healthy observations.
6. **Ticket recovery.** Explicit investigation requests recover the matching ticket from earlier message history instead of accepting the latest unrelated session. Local-mode switch-back now works; backend checkpoint recovery and ID-less answers to the active ticket remain covered.

Saved parser interpretations are repaired using the original observation and evidence ID. This includes generic VPN error types, reversed peer-negation interpretations, and unsupported self-correcting statements. No new user response or tool evidence is fabricated by migration.
