## Included in each article

- Discriminating questions and concrete eligibility observations.
- Exact SELF_SERVICE step IDs and reversible user instructions.
- Success criteria requiring the original task to work and explicit user confirmation.
- Exclusions, stopping conditions and human-escalation boundaries.
- Official product-documentation source link.
- Explicit local-only provenance and no backend-resolution authorization.

User observations remain USER_RESPONSE evidence. No endpoint inspection tool was invented, no USER_RESPONSE was relabeled TOOL_CHECK, and no article is presented as an executed fix. User-controlled settings are distinguished from managed settings. The guides do not collect credentials, change security controls, delete data, install drivers or send messages.

## Agent integration

Symptom wording for the new endpoint topics now generates the existing LOCAL_ENDPOINT candidate where appropriate. Wi-Fi and printer guides use the existing WIFI_FAILURE and PRINTER_OFFLINE categories. Scenario codes identify specific settings-level subtypes without inventing backend diagnosis enums.

Relevant retrieved guides are exposed as available_self_service_guides in structured agent results, including eligibility evidence, steps, success criteria and stop conditions. They are marked NOT_EXECUTED, backend_registered=false, and authorizes_ticket_resolution=false.

This task adds and integrates the knowledge content. It does not add a complete new conversational step-progress/confirmation state machine for these 12 scenarios. Normal chat continues the existing diagnostic flow; guide availability in the structured result is not proof that an end-to-end walkthrough was completed.
