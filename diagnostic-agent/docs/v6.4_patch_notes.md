## Unavailable definitions

KB-025 / ACCOUNT_LOCKED_POLICY and KB-026 / VPN_CLIENT_ISSUE were not returned by focused symptom searches, exact diagnosis-code searches or alternate local-symptom searches. Both IDs are also absent from the supplied backend article file. The live knowledge API returns approved searchable records only, so this is not proof that no unapproved live record exists.

These two articles remain owner-approved local diagnostic guidance, with agent_resolvable=false. They have not been registered, approved, or fabricated in the backend. Native diagnostic review mode continues to mark bundled knowledge as backend_reference=false, so their unavailable article IDs are not sent as backend foreign keys.

## Preserved history and behavior

Existing live-backend versions, exact step IDs, conditions, approval flags and specialist restrictions are authoritative for matching IDs. Only KB-001 remains an agent-resolution candidate. The richer local reviewed definitions were archived in docs/pre_backend_alignment_articles.json before replacement. Approval versions and content hashes were refreshed; original review decisions remain in approval history and earlier review records. Policy activation remains unapproved.

Some backend definitions contain generic diagnostic questions. Their text was copied exactly, rather than silently improved in the backend. Existing built-in discriminating questions are preserved.

Alignment exposed one retrieval defect: limiting lexical results before filtering to current candidate diagnoses let generic unrelated articles crowd out DNS guidance. Candidate filtering now occurs before the result limit. This changes retrieval scope, not backend article content or diagnostic evidence. A regression test verifies that a relevant lower-scoring article is not crowded out.
